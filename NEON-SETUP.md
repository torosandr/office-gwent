# Бесплатное постоянное хранение в Neon

Код поддерживает PostgreSQL через переменную окружения `DATABASE_URL`.
Профили, монеты, колоды, персонажи, коллекции, партии миниаппа, наборы и
использованные промокоды хранятся в одной базе. Текстовый webhook-бот использует
те же профили. Если подключение недоступно, действия не сохраняются в запасной
временный файл: сервер сообщает ошибку, чтобы не возникло двух разных коллекций.

## Настройка

1. В https://console.neon.tech создайте проект `office-gwent` на **Free**.
   Выберите ближайший к серверу Render регион. Платный тариф не нужен.
2. В проекте нажмите **Connect** и включите **Connection pooling**.
   Скопируйте строку подключения целиком. Она начинается с `postgresql://`,
   содержит `-pooler` в имени сервера и `sslmode=require`.
3. Перед переключением сохраните доступные текущие данные и согласуйте их
   источник. Файлы на вашем компьютере и `users.json` из Git не обязательно
   содержат последние изменения работающего сервера. Один лишь список рейтинга
   не является полной резервной копией.
4. В Render откройте именно сервис игры → **Environment**. Добавьте
   `DATABASE_URL`, значение — строка из Neon. Не помещайте её в код, Git,
   скриншот или сообщение чата.
5. Убедитесь, что **Build Command** = `pip install -r requirements.txt`,
   **Start Command** = `python miniapp_server.py`. Обновлённый Blueprint содержит
   эту команду сборки, но проверьте её и в настройках уже созданного сервиса.
6. Опубликуйте подготовленный код и запустите деплой после настройки базы.
   При первом запуске сервер создаст таблицы и один раз импортирует начальные
   профили бота и историю `used_by` из файлов. Повторные запуски не заменяют
   актуальные данные этими файлами.
7. Проверьте коллекцию, рейтинг, персонажа и наборы. После повторного деплоя
   прогресс должен остаться тем же. Эта проверка подтверждает подключение;
   успешные локальные тесты сами по себе его не подтверждают.

Документация: https://neon.com/docs/get-started/connect-neon

## Резервные копии на компьютер

Инструмент `database_backup.py` получает пароль только из окружения
`DATABASE_URL`. Не передавайте строку подключения аргументом команды.
Установите зависимости из `requirements.txt` перед использованием.

```text
python database_backup.py export backups/office-gwent-backup-YYYY-MM-DD.json
```

Файл содержит игровые данные, но не пароль Neon или токен бота. Храните его
локально и не публикуйте: внутри находятся профили игроков и хеши сессий.
Существующая копия не перезаписывается. Экспорт получает согласованное состояние
всех таблиц; игра может кратко ждать завершения операции.

Восстановление — только в новую пустую базу; существующий прогресс не удаляется:

```text
python database_backup.py restore backups/office-gwent-backup-YYYY-MM-DD.json
```

Если имеется актуальная SQLite-база прежнего миниаппа, её можно импортировать
в пустую Neon-базу до первого запуска сервера:

```text
python database_backup.py import-sqlite path/to/miniapp.sqlite3
```

Файл-источник открывается только для чтения. Профили из `users.json` объединяются
с импортированными профилями: экземпляры каждой карты берутся по максимуму,
чтобы не удвоить ранее скопированные карты. Для переноса актуальных профилей
бота используйте актуальный файл, заданный через `GWENT_USERS_FILE`.
Ошибка импорта отменяет весь перенос. Восстановление резервной копии не
добавляет поверх неё старые профили из Git.

## Локальная игра

`python miniapp_server.py --local` продолжает использовать SQLite и не
подключается к Neon, даже если `DATABASE_URL` задан. Так тестовые игроки и
демонстрационные промокоды не попадут в рабочую базу.
