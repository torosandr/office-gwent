# Графический Офисный Гвинт

## Запуск на этом компьютере

Дважды нажмите `Start-MiniApp.cmd` в папке Chat-24 и откройте http://127.0.0.1:8765.
Окно запуска держите открытым. Чтобы остановить сервер, нажмите Ctrl+C.
Если сервер уже работает, второй экземпляр запускать не нужно.

Первый игрок: http://127.0.0.1:8765/
Второй игрок: http://127.0.0.1:8765/?seat=2

Войдите под двумя именами, создайте партию в первом окне и введите её код во втором.
На телефоне этот локальный адрес недоступен: текущий сервер слушает только этот компьютер.

## Что работает

- Создание партии и присоединение по шестизначному коду.
- Карты в руке, существа на столе, кофе и стресс.
- Розыгрыш существ и заклинаний, подсветка допустимых целей.
- Атаки, способность героя, конец хода и сдача с подтверждением.
- Автоматическое обновление поля примерно раз в 1,5 секунды в открытом окне.
- Восстановление партии после обновления страницы, закрытия окна и перезапуска сервера.
- Однократное начисление победы и монет, проверка очереди и версии поля.

Нажмите карту в руке, чтобы разыграть её. Для атаки нажмите своё готовое существо,
затем подсвеченную цель. Спящее существо атаковать не может.

Локальные входы двух окон сохраняются раздельно в браузере на семь дней.
Удаление данных сайта удаляет доступ к локальному тестовому профилю; отдельного
восстановления гостевого аккаунта в первой версии нет.

## Хранение и совместимость

Используется тот же `battle.py`, `player.py`, `unit.py` и `cards.json`, что и у бота.
Состояние графических партий сохраняется в `miniapp.sqlite3` рядом с сервером.
Это отдельный режим: текстовые партии бота и графические партии не объединяются.
Рабочие `users.json` и промокоды не изменяются.

При первом подтверждённом входе Telegram сервер может прочитать профиль из файла
пользователей, указанного в `config.py`, и скопировать имя, героя, колоду, победы и монеты
в SQLite. Дальнейшая статистика графической версии хранится отдельно. Локальные
тестовые игроки всегда создаются с чистым профилем. Редактор колоды, магазин и
объединение статистики с текстовым ботом в первую версию не входят.

Публичный API передаёт игроку только его собственную руку; состав колоды и рука
соперника в ответ не включаются. Все изменения партии и награды сохраняются
одной транзакцией SQLite. Снимки движка используют JSON, а не pickle.

## Проверки

`python _test_miniapp.py` — тесты входа, приватности, сохранения, одновременных
запросов, повторных действий, ошибочных целей и маршрутов HTTP.
Тесты используют отдельные временные базы, а не `miniapp.sqlite3`.

Сервер и сайт не требуют новых пакетов: используются Python и стандартная библиотека,
браузерный JavaScript и CSS. Для существующих тестов бота по-прежнему нужен requests.

## Подключение Telegram позднее

Обработчик `/api/auth/telegram` уже проверяет HMAC подписи `initData` и время входа.
Подпись с изменённым содержимым, повторными полями или давностью больше часа
отклоняется. Затем выдаётся собственная семидневная сессия; в базе хранится хеш токена.

Для размещения потребуется HTTPS, публичный адрес, настройка кнопки Mini App
в BotFather и проверка на настоящем телефоне. Запуск без `--local` отключает гостевой вход;
токен читается из `TELEGRAM_BOT_TOKEN` либо существующего `TOKEN`/`BOT_TOKEN` в config.py.
Адрес обратного прокси задаётся через `MINIAPP_PUBLIC_URL`. Токен бота не передаётся в браузер.

Текущий HTTP-сервер предназначен для локальной проверки. До публичного запуска
нужно настроить промышленное размещение, ограничение частоты запросов, резервирование
SQLite и жизненный цикл старых партий. Сам факт готовности проверки Telegram
не означает, что приложение уже опубликовано или подключено к боту.

Официальная схема проверки: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app


## Персонажи, промокоды и пакетики

В миниаппе `/api/heroes` и `/api/hero` выбирают персонажа для следующей партии.
Рейтинг показывает доступные виды карт (включая базовые) и число экземпляров,
фактически полученных в коллекцию. Закрытые наборы в эти числа не входят.

`POST /api/promo` резервирует применение кода и запечатанный пакетик в одной
SQLite-транзакции. Награда сохраняется в пакетике на момент получения; открытие
через `/api/packs/open` начисляет этот состав один раз. Повторный запрос с тем же
ID возвращает результат без повторного начисления. Наборы имеют существующий
фиксированный состав из sets.json, а не случайный лут. Старые наборы профиля
бота уже выдали карты и не превращаются в повторные закрытые пакетики.

Webhook-бот использует тот же журнал применений промокодов, но сохраняет
прежнее мгновенное начисление. Исторические used_by из promo_codes.json тоже
учитываются. Новые применения хранятся в SQLite, а не в Git.

### Постоянное хранение

Профили, наборы и журнал промокодов находятся в той же SQLite-базе, что и
миниапп. Для размещения файла на постоянном диске задайте MINIAPP_DATABASE_PATH
(например, /var/data/miniapp.sqlite3; каталог должен существовать).
Без постоянного диска/базы на Render файл может исчезнуть при деплое или
замене экземпляра. Бесплатный Blueprint проекта не подключает постоянный диск.
Не добавляйте SQLite-базу или изменённые игровые профили в Git.
